# ReadMe：agent 技能

ReadMe 跑在用户自己的电脑上，读聊天导出文件，整理出「约好的事、答应过的事、改了的安排、每个人的画像」，到日子提醒用户。你负责三件事：

1. 把新聊天带进来
2. 整理（你自己就是整理用的 AI，不用用户另填密钥）
3. 按时自动做前两件

对用户说话用用户的语言，结论先行，一两句说清做了什么。

## 必须遵守

- **只用聊天软件官方的导出功能。** 不安装、不运行任何解密工具、抓取工具或读取聊天数据库的工具；不登录用户的聊天账号；不绕过任何软件的限制。
- **微信没有官方导出。** 遇到微信就跳过，告诉用户：「微信官方不支持导出聊天记录，需要你自己解决（可以参考其他开源项目）。」不要推荐、下载或运行任何具体工具。
- **聊天内容只在本机和你自己用。** 不发到别的服务，不复制到 ReadMe 数据目录以外的地方，汇报时不贴聊天原文，只说条数和整理出的标题。
- **只用下面列出的命令。** 不改 ReadMe 的代码和设置，不直接读写它的数据库。
- 用户在「设置 → 隐私」里设成「不发给 AI」的人，命令本身就不会给你，不要想办法去读。

## 怎么运行 ReadMe 的命令

下面的 `radar` 指用户给你的那条命令去掉末尾的 `guide agent`，通常是下面两种之一：

```bash
npx readme-app <命令>      # 用一条命令装的
node <ReadMe 程序目录>/bin/radar.mjs <命令>           # 克隆了代码的
```

数据目录默认是 `~/.personal-radar`。用户告诉你别的数据目录时，每条命令前都加上 `RADAR_DATA_DIR=<那个目录>`。所有命令都直接读写数据目录，ReadMe 网页开着或关着都可以运行。需要 Node.js 22.13 以上。命令提示「还没有 ReadMe 的数据库」时，说明用户还没打开过 ReadMe：先运行一次 `radar`（不带命令，会打开网页），再继续。

## 一、把新聊天带进来

先问清楚（第一次时问，之后记住）：要跟进哪些人、各在哪个软件上。然后按软件处理：

| 软件 | 怎么拿到新聊天 |
|---|---|
| LINE（电脑版） | 打开那个人的聊天 → 右上角菜单 →「保存聊天记录」（日文界面是「トーク履歴を保存」），存成 .txt。你能操作电脑界面的话可以替用户点；不能就提醒用户点。 |
| WhatsApp | 只能在手机上导出：聊天 → 更多 → 导出聊天 → 不含媒体。你做不了，提醒用户导出后放到电脑上。 |
| Telegram（电脑版） | 聊天右上角 ⋮ →「导出聊天记录」→ 格式选 JSON。 |
| Instagram / Messenger、Discord、Google Chat | 运行 `radar guide export` 看各软件怎么导出。 |
| 微信 | 跳过，按上面「必须遵守」里的话告诉用户。 |

拿到文件后导入（只会加新消息，重复导入不会重复）：

```bash
radar import <文件…>                 # 读不出「哪个是你」时加 --me "用户在聊天里的名字"
radar import <文件…> --dry-run       # 只预览，不写入
```

用户在 ReadMe 里设了「自动导入文件夹」的话，把文件存进那个文件夹也行，ReadMe 每 5 分钟会自己导入。

## 二、整理

第一次整理前，运行 `radar guide extract`，完整读一遍整理规则和提交格式，之后每次按它来。

```bash
radar ai status                          # 每个人还有多少新消息没整理
radar ai next --session <id>             # 取下一段聊天（已按用户的隐私规则隐藏了手机号、卡号等）
radar ai submit --file <结果.json>        # 交回整理结果；校验通过才会推进进度
```

做法：
1. `radar ai status`，挑出还有新消息的人。
2. 对每个人循环：`next` → 按整理规则写结果 JSON 到一个临时文件 → `submit`。`next` 显示 `DONE` 就换下一个人。
3. `submit` 报错时，按错误信息改好再交同一份；整理没成功不会推进进度，下次会重新给你同一段，不会漏也不会重复。
4. 一次最多整理每个人 6 段，剩下的留给下次，避免一次用掉太多额度。
5. 每个人整理完后查一次重：`radar ai dupes --session <id>` 列出几对看起来重复的记录（显示 NONE 就跳过）。逐对判断，只有意思完全一样才合并，话题相近但内容不同的不要合并；把确定重复的写成 `{"session":"<id>","groups":[{"keep":留下的编号,"drop":[合并掉的编号],"title":"可选的新标题"}]}`，用 `radar ai merge --file <文件>` 交回。没有重复就跳过。
6. 有新记录的人，再更新一下人物分析：`radar ai digest --session <id>` 取材料，按 `radar guide analysis` 里的规则写好，`radar ai analysis --file <分析.json>` 交回。

## 三、按时自动运行

用你所在工具自带的定时任务功能（各个 agent 的叫法不同：定时任务、计划任务、自动化、cron），建一个每天固定时间的任务，比如每天 21:30，内容是：

> 按 ReadMe 的 agent 技能：导入新聊天，整理还没整理的消息，最后用一两句话告诉我新增了哪些要处理的事。

注意：任务必须在用户这台电脑上运行（ReadMe 的数据只在这里），云端运行的任务读不到。电脑睡眠时任务不会执行。

## 汇报格式

一两句话，例如：

> 导入了 2 个人的新聊天（共 312 条），新整理出 4 件事：周六下午两点看房、答应周末帮对方修电脑……打开 ReadMe 的「今天」可以看到。

不贴聊天原文；出错就说哪一步、什么错，下次会怎样。
