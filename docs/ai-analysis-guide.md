# 人物分析规则

先用 `radar-ai digest --session <会话>` 读取素材：互动事实，加上已整理的全部记录（每条带一句关键原话）。
分析的读者是用户本人（"我"），目的是帮 TA 更了解这个人、更好地相处。

## 原则
- **每个观点都要有依据**：`items` 里列出支撑它的记录编号（#编号），至少 1 条，最好 2–4 条
- **事实和推测分开**：`basis: "fact"` 只用于记录里直接写明的内容（对方自己说的、明确发生过的事）；你归纳出来的性格、相处模式一律是 `basis: "inference"`
- **不打分**：不写亲密度、好感度、契合度之类的数字或等级，也不预测"会不会在一起"
- **不贴心理标签**：不用"焦虑型依恋""回避型人格""NPD"这类诊断式说法，只描述看得到的行为和对方自己说过的话
- **公平**：对方的优点、你们相处顺利的地方，和摩擦一样要写。写摩擦时写清楚发生了什么、后来怎么解决的，不评判谁对谁错
- **写人话**：每条 1–2 句，具体，避免"这个人很有趣"这种空话。能举例就举例（"会提前一周排好你们见面的日子"）
- **范围**：只分析这个人、和你们之间的关系。聊天里提到的第三方不展开

## 结构（sections，按这个顺序，没有依据的部分可以省略）
1. **性格特点**：做事和说话的风格
2. **在意什么**：对方明确说过的需要、讨厌的事、看重的东西
3. **沟通方式**：对方习惯怎么表达、情绪上来时怎样、什么样的回应对方受用
4. **生活与节奏**：工作、作息、爱好、近况
5. **你们的关系**：相处模式、谁主动、常一起做什么、重要的经历和转折（结合互动事实里的按月数据）
6. **摩擦与修复**：出现过的分歧，以及是怎么化解的
7. **相处建议**：根据以上内容给出 3–5 条具体可做的建议，每条也要有依据

如果是以某个话题（工作、投资、兴趣）为主的朋友关系，可以把第 5–6 部分换成「你们聊什么」「观点上的异同」。

## 提交格式（写成文件，再执行 `radar-ai analysis --file 文件`）
```json
{
  "session": "<会话 id>",
  "summary": "两三句总览：对方是什么样的人，你们现在是什么关系状态（写成推测的语气）",
  "sections": [
    {"title": "性格特点", "points": [
      {"text": "做事很有计划，会提前排好两人见面的日程", "basis": "inference", "items": [27, 30, 33]}
    ]}
  ]
}
```
